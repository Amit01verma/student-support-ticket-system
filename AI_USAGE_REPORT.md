# AI / Tool Usage Report

## AI Tools Used

- **ChatGPT**
- **GitHub Copilot**

AI assistance was used during development for planning, implementation guidance, code completion, debugging support, documentation, and validation. AI-generated suggestions were reviewed, adapted, and tested before being used.

## What I Asked AI To Do

1. Help break down the Student Support & Ticket Management System into practical frontend, backend, database, and workflow components.
2. Help design and implement the ticket lifecycle, including status, priority, assignment, SLA tracking, activity history, dashboard statistics, and staff workflows.
3. Help with code completion, debugging, configuration issues, documentation, and deployment-related problems.

## Prompt That Was Most Useful

> "I want to build a Student Support & Ticket Management System for students to raise requests and for staff to own, prioritize, process, and resolve them. Help me design and implement the complete flow step by step, including ticket statuses, priorities, assignment, SLA tracking, activity history, dashboard visibility, and important edge cases."

This helped translate the assignment requirements into a concrete product workflow and implementation plan.

## Code Generated by AI

AI assistance was used for parts of the implementation, including:

- Express route/controller patterns for ticket creation, retrieval, updates, statistics, and staff listing.
- MongoDB/Mongoose model structures for users, tickets, and ticket activities.
- React component and page implementation patterns for the dashboard, ticket list, ticket creation, ticket details, authentication, and activity timeline.

- Configuration and deployment fixes such as CORS handling and Vercel SPA routing.

The generated/suggested code was reviewed, adapted to the project structure, and tested rather than being used without verification.

## Code I Modified

I modified and integrated the AI-assisted code to match the project requirements, including:

- Ticket fields, statuses, priorities, categories, and SLA rules.
- Student/staff/admin roles and demo authentication flow.
- Ticket assignment and status/priority update behavior.

## AI Output That Was Wrong

An initial database configuration did not correctly target the application's MongoDB database. The connection string was using the default `test` database instead of `student-support-system`, which resulted in a MongoDB permission error when the application tried to access the users collection.

During development, there were also implementation mismatches around API responses/routes and production configuration that required correction.

## How I Identified the Problem

I identified these issues by running the application locally, checking backend terminal errors, testing API endpoints, inspecting browser errors, and validating the deployed frontend and backend.

For example, the MongoDB error showed that the application was attempting to access:

`test.users`

while the database user had permissions for:

`student-support-system`

## How I Fixed It

I updated the MongoDB connection string to explicitly use the `student-support-system` database, then restarted and retested the backend.

I also added/fixed the required API routes, aligned frontend requests with backend responses, added the production Vercel origin to CORS, and configured Vercel SPA rewrites so direct React routes work correctly.

The final system was validated through local testing and production testing with the deployed React frontend, Express backend, and MongoDB Atlas database.
